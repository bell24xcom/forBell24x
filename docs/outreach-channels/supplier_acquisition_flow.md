# Supplier Acquisition Workflow
**Project:** VyaparSethu  
**Date:** 2026-08-26  
**Constraint:** No Meta WhatsApp Cloud API. All steps use channels confirmed active in `communication_audit.md`.

---

## Overview

The target flow converts a discovered supplier into a verified, RFQ-responding, quoting member of the Trade Network.

```
Supplier discovered
  → Day-0 outreach (wa.me or email)
  → Claim profile (/claim/{token} or /auth/phone-email)
  → Profile completion (supplier dashboard)
  → Verification (GST / Udyam)
  → RFQ matching (auto-notify on new open RFQ in their category)
  → Quote submission (/api/rfq/quotes)
```

---

## Stage 1: Supplier Discovery

**Sources (current):**
- Manual import: `POST /api/admin/import-suppliers` (CSV or JSON batch)
- Lead scraper: `src/lib/lead-engine/scraper.ts` → `POST /api/leads/import` (DPDP-compliant)
- Founder direct sourcing (WhatsApp contacts, IndiaMart listings, referrals)
- GST directory lookups (public data, no scraping consent issue)

**DB state created:**
- `User` row with `role: SUPPLIER`, `isClaimed: false`, `outreachCount: 0`
- `phone` and/or `email` populated; `company`, `location`, `gstNumber` where available

**Gate before outreach:**
- `phone` OR `email` must be non-null
- `trustScore` computed (or default 50 until first cron run)

---

## Stage 2: Day-0 Outreach

**Primary channel: wa.me link (founder/operator sends)**

Route: `GET /api/admin/outreach/bulk-wa?dryRun=true` → preview → open wa.me link in operator's WhatsApp → send manually.

Admin UI path: `/admin/outreach` → Bulk WA panel → operator opens link for each supplier.

Message template (from `supplier-drip-engine.ts`):
```
Namaste! 🙏

Your business "{companyName}" has a verified profile on VyaparSethu —
India's B2B Supplier & Buyer Network.

Verified buyers are searching for your products right now.

Claim your FREE profile in 2 minutes:
{claimLink}

— Team VyaparSethu
vyaparsethu.com
```

**Secondary channel: Claim invitation email**

Route: `POST /api/admin/send-invitations` — sends email to all `isClaimed: false` suppliers with a real email address.

Subject: `{company} — Claim your profile on VyaparSethu`  
CTA: Button → `/auth/phone-email?claim={supplierId}`

**Tracking:**
- `user.outreachCount` increments on each send
- `user.lastOutreachAt` set to now
- `user.claimToken` set (UUID) — claim link is single-use, tied to supplier row
- `InteractionMemory` row created with `actionType: 'day1_wa_sent'`

**Eligibility guard (already in bulk-wa route):**
- `role: SUPPLIER`
- `isClaimed: false`
- `outreachCount < 3`
- `phone` not null
- `lastOutreachAt` is null OR > 2 days ago

## Stage 3: Drip Follow-Up (Days 3, 7, 14)

Route: `GET /api/cron/supplier-drip` (Vercel cron) calls `getDripsDue()` from `supplier-drip-engine.ts`.

**Day-3 message:**
```
Hi {company} 👋 Reminder about your free verified supplier profile on VyaparSethu.
Buyers in your cluster are actively posting Requirements.
Claim it in 2 min: {claimLink}
```

**Day-7 message:**
```
Hi {company} — It's been a week. Verified buyers are searching your category
on VyaparSethu right now. Your profile slot is still reserved: {claimLink}
```

**Day-14 message (final):**
```
Hi {company} — Last message. We're completing our verified supplier list for
your category this week. Claim your free profile before it's offered to a
competitor: {claimLink}
```

Each drip logs `actionType: drip_day3 / drip_day7 / drip_day14` in `InteractionMemory`.  
After day-14, no further automated messages. Supplier stays in DB as `isClaimed: false`.

**Delivery method:** wa.me links are generated by the engine. Operator opens admin drip panel and clicks to send. For fully automated sending: MSG91 Promotional SMS (after DLT registration — see `communication_audit.md`).

## Stage 4: Profile Claim

**Claim URL:** `/claim/{token}` or `/auth/phone-email?claim={supplierId}`

**What happens on claim:**
- `POST /api/auth/claim` — supplier verifies phone via MSG91 OTP
- `user.isClaimed` set to `true`
- `user.claimToken` cleared
- Supplier is redirected to dashboard

**Completion gate:**
After claim, prompt supplier to complete profile via dashboard `Supplier Profile` page.

Required for verification:
- Company name
- Phone (already verified)
- Location (city/state)
- Category/categories (what they supply)
- At least one product listed

Optional but recommended:
- GST number (triggers `POST /api/supplier/gst` verification)
- Udyam number
- WhatsApp number (for Business Conversations)
- Website
- Business description

---

## Stage 5: Verification

**GST Verification:**
Route: `POST /api/supplier/gst` — validates GST number format and checks government registry.  
On success: `user.gstNumber` stored, `user.isVerified` set to `true`.

**Udyam Verification:**
Field stored in `user.udyamNumber`. Manual verification by admin currently (no automated Udyam API).

**Trust Score:**
Computed by daily cron at 2 AM IST via `POST /api/cron/daily`.  
Formula: 30% Payment History + 20% On-time Delivery + 15% Response Speed + 15% Repeat Orders + 10% Dispute Rate + 10% Verification Strength.  
Stored on `user.trustScore`. Never computed real-time.

**Verification badge visible to buyers:**
`user.isVerified: true` shown on supplier card. `trustScore` visible in quote context.

---

## Stage 6: RFQ Matching

**Automatic matching:**
Route: `POST /api/rfq/match-suppliers` — called after RFQ creation. Matches suppliers by `category` field in `user.preferences`.

**Supplier notification on match:**
Current implementation: email to supplier via `sendEmail`.  
Gap: no `Notification` row created in DB on match. Add `prisma.notification.create` in match route for in-app notification.

**Supplier view of available RFQs:**
Route: `GET /api/supplier/leads` — returns public, open RFQs. Buyer contact hidden by default.  
Supplier sees: category, product title, quantity, budget (if set), location, urgency, status.  
Buyer name/company: masked as `••• •••••` until unlocked.

---

## Stage 7: Quote Submission

Route: `POST /api/rfq/quotes` or `POST /api/quote`

Supplier submits:
- Price
- Quantity they can supply
- Delivery days
- Notes / terms
- Timeline

On quote submitted:
- `quoteReceivedEmail` fired to buyer
- `deal/select` route used by buyer to accept a quote → Deal created

**Lead unlock (optional, credit-based):**
Route: `POST /api/leads/unlock` — costs 1 credit. Reveals buyer name + company.  
Supplier's `UserCredits.credits` must be ≥ 1.  
After unlock: `LeadSupplier` row created with `unlocked: true`.

## Conversion Funnel Tracking

```
Discovered       → user.role = SUPPLIER, isClaimed = false
Outreached       → outreachCount > 0
Claimed          → isClaimed = true
Profile Complete → preferences.categories not empty AND phone verified
Verified         → isVerified = true (GST check passed)
RFQ Matched      → InteractionMemory: rfq_matched
Quote Submitted  → Quote row exists for this supplier
Deal Won         → Deal row with supplierId = this supplier
```

Admin summary available via `getOutreachSummary()` in `supplier-drip-engine.ts`.

---

## Success Criteria for Phase 1 (First 10 Verified Suppliers)

1. ≥10 suppliers with `isClaimed: true` AND `isVerified: true`
2. ≥5 suppliers have submitted at least one quote
3. ≥1 deal closed through the platform
4. Conversion rate (claimed / outreached) ≥ 15%
5. Zero Meta/Cloud API dependency in any live path
